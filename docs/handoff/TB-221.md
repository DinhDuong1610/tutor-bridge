# TB-221 Gửi X-Operation-Id trên các lệnh ghi đã khai trong hợp đồng

## Mục tiêu
Mọi lệnh ghi trên `dev` mà hợp đồng khai `X-Operation-Id` gửi header này, bằng id receipt, cả khi phát lại cùng khóa. App dùng id này để tra `getCommandStatus` (#75).

## Kế hoạch
- [ ] `platform/api/Receipted<T>(T value, UUID operationId)`: kết quả của một lệnh có receipt.
- [ ] Service trả `Receipted<…>`: `NeedService.create`, `update`, `confirm`; `MatchingRunService.create`; `OfferService.send`, `respond` (reject, cancel). Phát lại trả `receipt.id()` của receipt đã lưu, nên cùng id.
- [ ] Controller gắn header `X-Operation-Id`: `NeedController`, `MatchingRunController`, `OfferController`.
- [ ] `Contract.matches()`: phản hồi mà hợp đồng khai `X-Operation-Id` phải có header này và là uuid.
- [ ] Test HTTP mỗi lệnh: header có mặt, phát lại cùng khóa trả cùng id, `getCommandStatus` theo id trả đúng lệnh. Test của `Contract`: thiếu header thì báo vi phạm.
- [ ] Làm hỏng code để thấy test đỏ (test commit trước).

Theo `transaction-change` (việc này đụng idempotency):
- **Thứ tự khóa, ranh giới giao dịch, kiểm lại, commit:** không đổi. Chỉ đổi giá trị trả về của khối `transactions.execute`, thêm `receipt.id()` đã có sẵn trong đó.
- **Không I/O ngoài trong giao dịch:** không thêm gì vào trong giao dịch.
- **Header gửi sau commit:** controller chỉ gắn header khi `transactions.execute` đã trả về, tức là đã commit (INV-21).
- **Thất bại:** lỗi trong giao dịch vẫn rollback cả receipt như cũ. Phản hồi lỗi không có header, và hợp đồng chỉ khai header trên phản hồi thành công.
- **Phát lại:** `begin` trả id của receipt đã lưu, nên phát lại cùng khóa trả cùng id (INV-20, BR06).

File dự kiến đụng: `platform/api/Receipted.java`; `classes/internal/{NeedService,MatchingRunService,OfferService}.java`; `classes/web/{NeedController,MatchingRunController,OfferController}.java`; `src/test/java/com/tutorbridge/Contract.java` và test.
